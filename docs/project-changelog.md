> 条目按时间倒序；细节以代码与 PR 为准。

## 2026-08-07

### 本机 Docker 全栈 → 内网机房可迁移

| 项 | 内容 |
|----|------|
| **问题** | 原先 Compose 只起库、Ollama 绑宿主机，无法一键给别人用，也不便搬到公司内网。 |
| **方案** | ① `profile: full` 起 db+ollama+migrate+web；② `.env.docker.example` 外置密钥；③ DB 仅 `127.0.0.1`；④ 生产校验 JWT、v1 限流、health 探活 Ollama、可选 CORS；⑤ `docs/deploy-local-intranet.md`；⑥ macOS 用 Colima 替代收费 Docker Desktop。 |
| **结果** | 本机 `docker compose --profile full up --build -d` 即可注册使用；改 `.env` 可迁内网机房。 |

### 对外知识问答 API + API Key（第一期）

| 项 | 内容 |
|----|------|
| **问题** | 控制台问答仅 JWT 可用，外部系统无法以应用 ID + Key 调用知识库问答。 |
| **方案** | ① `ApiKey` 模型（SHA-256 存哈希，列表脱敏）；② JWT 管理 CRUD/重置；③ 抽取 `runChatAnswer`，新增 `POST /api/v1/apps/chat`（Bearer `sk-ks-…`，`agent_id`=知识库 ID 或数组）；④ `/developer/keys` + `/developer/playground`（多知识库调试）。 |
| **结果** | 可用 API Key 对名下知识库做 JSON/SSE 问答；明文密钥仅创建或重置时展示一次；调试页支持多选联合检索。 |

### Qwen3 流式「检索立刻返回、正文空等数秒」

| 项 | 内容 |
|----|------|
| **问题** | SSE 先推 references/meta，chunk 要等好几秒才出现。 |
| **原因** | Ollama 对思考模型把推理写在 `delta.reasoning`，旧逻辑只读 `delta.content`，思考阶段被丢弃。 |
| **方案** | 流式/非流式均兼容 `reasoning` / `reasoning_content`，映射为已有 `<thinking>` / `<conclusion>`；检索后发 `status: generating`。 |
| **结果** | 思考过程也会立刻流式输出，空窗明显缩短。 |

### 用户鉴权 + 多用户数据隔离

| 项 | 内容 |
|----|------|
| **问题** | 原先无登录、知识库/文档/会话全局共享，无法按用户隔离，也不适合演示多租户。 |
| **方案** | ① `User` 模型 + KB/ChatSession.`userId`；② 自建 JWT，客户端 `localStorage` + Bearer；③ 登录即注册（账号不存在则自动创建）；④ 业务 API 按归属隔离；⑤ 可关闭登录弹窗（邮箱或手机号）；无主旧数据由首个登录用户认领。 |
| **结果** | 未登录可浏览壳层；登录后仅见本人数据；分享会话只读仍公开。 |

## 2026-08-06

### 评测集 + 旧库重解析 + 检索融合说明

| 项 | 内容 |
|----|------|
| **问题** | 切分/融合改完后缺量化回归；就绪文档 UI 不能一键按新切分重跑；答辩需讲清「为何这样排」。 |
| **方案** | ① `/retrieval/eval` + `POST /api/retrieval/eval`：按语料分套（软考/博客/混合），应命中与应拒答分计 Hit@K·MRR·正确拒答率；② 文档库「按新切分重解析」与 `scripts/reparse-kb.mjs`；③ README + 评测页固定四步讲融合。 |
| **结果** | 演示路径：重解析 → 选对应用例集跑评测 → 对照工作台；用例已对齐本地真实文件名。 |

### 混合检索：加权融合分统一排序与展示

| 项 | 内容 |
|----|------|
| **问题** | 混合检索曾用 RRF 排位、界面用 max(向量,关键词)，顺序与分数不一致；问答与检索两侧也不统一。 |
| **方案** | 两路候选取并集并做阈值过滤；最终 `score = w·vector + (1−w)·keyword`（单路则用该路分数，默认 w=0.6）；检索 API、知识问答引用、检索工作台均按该分降序。 |
| **结果** | 排序与展示分一致；可通过 `RAG_HYBRID_VECTOR_WEIGHT` 调节语义/关键词偏好。 |

### 引用来源按检索分数降序展示

| 项 | 内容 |
|----|------|
| **问题** | 知识问答「引用来源」序号与界面分数不一致（如 0.817 排在 1.000 前）。 |
| **原因** | 混合检索按 RRF 融合排序，展示用的是向量/关键词相似度分数，二者顺序不同。 |
| **方案** | 父子块展开后、chat `mapReferences`、前端引用列表与检索工作台结果均按 `score` 降序；展示序号与分数对齐。 |
| **结果** | 引用列表高分在前（如 1.000 → 0.832 → 0.817）。 |

### RAG 切片升级：Recursive + Parent-Child

| 项 | 内容 |
|----|------|
| **问题** | 「智能切分」实为段落拼装，无真 overlap、无层级；检索要么过碎要么上下文不足，难对齐主流 RAG。 |
| **方案** | ① Recursive 分隔符优先级（标题→段落→句子）+ 块间 overlap；② 默认开启父子切片：子块 embedding 检索，命中后 expand 父块喂模型；③ `Chunk.level/parentId`；④ 上传页增加父子开关，默认父 800 / 子约 40%。 |
| **结果** | 新上传/重试解析走新切分；旧文档需重试解析。列表只展示检索单元（leaf/child）。 |

### 解析失败修复：老格式 DOC/PPT、无文字图片、加密 Office

| 项 | 内容 |
|----|------|
| **问题** | 格式测试库中大量失败：`.doc`/`.ppt` 被 OfficeParser 拒绝；无文字图片 OCR 判失败；加密/损坏 pptx 报 ZIP 错误。 |
| **方案** | 引入 `word-extractor`（DOC）、`ppt-to-text`（PPT）；PPTX 校验 ZIP/加密并支持误后缀文本降级；图片 OCR 无文字时写入尺寸元数据切片；错误信息中文化。 |
| **结果** | 合法 DOC/PPT/无文字图片可入库；仅加密或损坏样本仍失败并给出明确提示。 |

### 文档在线预览：按格式渲染，不再直接下载

| 项 | 内容 |
|----|------|
| **问题** | 点击「本地文件 / 查看原文」直接打开 `/api/documents/.../file`，Office 等格式浏览器无法 inline 渲染，触发下载。 |
| **方案** | 新增 `/knowledge/preview` 与 `GET /api/documents/[id]/preview`：PDF/图片 iframe·img 内嵌；MD/TXT 渲染；HTML sandbox；DOCX mammoth 转 HTML；XLS/XLSX 表格 HTML；DOC/PPT/PPTX officeparser 正文预览。列表与切片页链接改指向预览页，原文件仍可通过「下载原文件」获取。 |
| **结果** | 各格式在站内即可预览，体验对齐百炼「在线查看」。 |

### 文档解析进度：SSE 推送替代前端轮询

| 项 | 内容 |
|----|------|
| **问题** | 文档列表页为实时显示解析进度，每秒轮询 `/api/documents`，请求频繁且延迟固定 1s。 |
| **方案** | 解析进度写入时 `publishDocumentProgress` 广播；新增 `GET /api/documents/stream`（SSE），连接时补发进行中快照，后续按 `document` 事件推送；列表页用 `EventSource` 订阅，无进行中任务时自动断开。 |
| **结果** | 进度条随入库/OCR/向量化即时更新，空闲时无轮询流量。 |

### 上传前索引设置：切片方式与最大分段长度（对齐百炼）

| 项 | 内容 |
|----|------|
| **问题** | 切片粒度与百炼差异大（如教材 PDF 仅 174 片 vs 百炼 1407 片）；无法在入库前配置切分策略与分段长度。 |
| **方案** | 上传向导改为两步：① 选择数据 ② 索引设置；`ChunkIndexSettings` 提供智能/长度/页/标题/正则/符号六种切分 + 10–6000 字符滑块（默认 600）；配置写入 `Document.chunkConfig`，解析时 `splitTextByConfig` 按策略切片。 |
| **结果** | 新上传文档可对标百炼「索引设置」；已有文档重试解析沿用库内配置（无则默认 600 智能切分）。 |

### PDF 提取与切片：对齐百炼粒度（1400+ 片级教材）

| 项 | 内容 |
|----|------|
| **问题** | 教材 PDF 在百炼智能切片约 1407 片且正文完整；本地仅 ~129 片，大量章节遗漏。 |
| **原因** | ① `pdf-parse` 对复杂 PDF 只抽到部分文字层，有字即返回、不触发 OCR；② 切片窗口 700 字偏大；③ 全量 OCR 默认仅 40 页。 |
| **方案** | 引入 `pdfjs-dist` 逐页提取，与 pdf-parse 取更完整结果；检测「每页字数过低」时对稀疏页 selective OCR；切片改为 512 字 / 64 重叠；`PDF_OCR_MAX_PAGES` 默认 1000。 |
| **结果** | 重试解析后切片数与正文覆盖应接近百炼；大 PDF OCR 补全耗时更长，进度条会显示「OCR 补全 x/y」。 |

### PDF 切片质量：清洗目录点线与 OCR 噪声

| 项 | 内容 |
|----|------|
| **问题** | 教材类 PDF（如系统集成教程）切片出现大量 `....23`、重复点线、目录行与正文混在同一 chunk，检索与阅读体验差。 |
| **原因** | `pdf-parse` 保留目录引导点线；原先直接按字符窗口切片，未处理 PDF 版式噪声。 |
| **方案** | 入库前 `prepareTextForChunking`：去掉纯点线行、将 `标题……页码` 规范为 `标题 · 页码`；PDF 连续目录行合并为带 `【目录】` 前缀的分组块再切片。 |
| **结果** | 新上传或重试解析的 PDF 切片更可读；已有文档需在列表点「重试解析」重新入库。 |

### 控制台布局：侧边栏与子页顶栏固定

| 项 | 内容 |
|----|------|
| **问题** | 切片详情等子页滚动时，左侧导航与「返回」顶栏一起被带走，操作不便。 |
| **方案** | 外层 `h-screen overflow-hidden` 锁视口；侧栏占满高度不参与滚动；`ConsoleSubpageLayout` 顶栏固定、内容区单独滚动；切片页工具栏移出滚动区（`fullHeight` + 列表独立 `overflow-y-auto`），避免 `sticky` 在「返回」与搜索栏之间漏出正文。 |
| **结果** | 滚动切片列表时侧栏与返回/搜索栏保持可见；文档列表页同理固定知识库标题与搜索工具栏。 |

### 混合检索（向量 + pg_trgm 关键词）

| 项 | 内容 |
|----|------|
| **问题** | 纯向量检索对专有名词、编号、表格字段等字面匹配弱，易漏召回。 |
| **方案** | 启用 `pg_trgm` + GIN 索引；检索与问答统一走 `searchChunks`：向量 leg（pgvector）与关键词 leg（trigram / ILIKE）并行召回，RRF 融合排序；向量/关键词分别阈值过滤（`RAG_MIN_SCORE` / `RAG_KEYWORD_MIN_SCORE`）；无 pg_trgm 或 `RAG_HYBRID=0` 时回退纯向量。 |
| **结果** | 检索工作台显示混合模式与 vec/kw 召回数；问答链路同步受益。`pnpm db:setup` 自动建扩展与索引。 |

### 扫描件 PDF 无法解析 → 引入 OCR 回退

| 项 | 内容 |
|----|------|
| **问题** | 上传「思维导图」等 PDF 后报错「未能从文件中提取到文本内容」，文档状态失败、0 切片。 |
| **排查** | `pdf-parse` 对样例文件返回 24 页、文本长度 0。对比同批次其它 PDF 可抽出文字。结论：该文件是**图片型/扫描件 PDF**（无可复制文字层），不是上传损坏。项目原先只做文字层抽取，**不支持 OCR/多模态识图**。 |
| **方案** | 文字层为空时自动 OCR：PDFium 渲染页面 → Tesseract（`chi_sim`）识别 → 再切片向量化。配置项见 `PDF_OCR_*`（默认开启）。 |
| **结果** | 扫描件可入库；OCR 有错字属预期，检索通常可用。大文件耗时更长，进度条会推进。失败文档可点「重试解析」。 |
